# Chẩn đoán R2 — 06/10/2026

## Đã xử lý sau khi thay cặp khóa mới

Người dùng đã thay cả hai S3 credentials trong file riêng. Toàn bộ 9 kiểm tra local đạt; từ Vercel, cả hai bucket trả 200 với boto3 và phép ký độc lập, HMAC xác nhận khóa cloud/local khớp. Backend cloud ghi/đọc ảnh private, xác thực và chuyển ảnh sang WebP, ghi ảnh public và đọc ảnh qua r2.dev đều đạt. Các object thử nghiệm đã được xóa; một object cũ còn sót dưới prefix thử nghiệm cũng đã được dọn.

Đã cập nhật hai biến sensitive trên Vercel và cấu hình local `.env` (0600, ngoài Git). 30 test liên quan media/governance/admin quality đạt trong 6.71 giây. Không thay đổi thuật toán ký S3 của backend để xử lý lỗi.

## Kết luận với cặp khóa cũ

R2 từ chối xác thực chữ ký S3 với cặp credentials hiện tại: **HTTP 403, `SignatureDoesNotMatch`** trên cả `pagefpt-staging-private` và `pagefpt-staging-public`.

Phép thử trực tiếp từ Vercel không có proxy, sử dụng endpoint đúng tài khoản và region `auto`. Ký bằng boto3 và ký AWS Signature V4 độc lập đều trả cùng lỗi. Phép ký độc lập cũng đã được đối chiếu và tạo chữ ký giống boto3.

Khả năng cao Secret Access Key không đúng cặp với Access Key ID. Chưa có metadata token hoặc một cặp khóa mới được kiểm chứng để kết luận chính xác thao tác nào khi tạo/copy khóa đã gây lỗi. Không kết luận giới hạn IP là nguyên nhân.

## Bằng chứng

| Kiểm tra | Kết quả |
|---|---|
| Backend local đọc đúng file người dùng lưu | Đúng; không có environment override |
| Access Key ID | 32 ký tự hex |
| Secret Access Key | 64 ký tự hex |
| Khóa trên Vercel có thừa khoảng trắng/xuống dòng | Không |
| Khóa trên Vercel khớp local | Đúng; kiểm tra HMAC, không in khóa |
| Endpoint trên Vercel | Đúng tài khoản `63f67f18e38b4396d4a1b622bcc78990` |
| Signing region | `auto` |
| boto3, kiểm tra cả hai bucket từ Vercel | 403 `SignatureDoesNotMatch` |
| Ký độc lập, kiểm tra cả hai bucket từ Vercel | 403 `SignatureDoesNotMatch` |
| Truy cập endpoint chẩn đoán chưa xác thực | 401 |
| Endpoint chẩn đoán trên domain website hiện tại | 404; snapshot kiểm tra không được promote |

Đường mạng trên máy local đi qua proxy FPT; TLS hợp lệ, kết nối trực tiếp timeout. Một số phép thử local trước đó đã thành công nhưng các phép thử sau trả `AccessDenied`. Các kết quả đó không đủ để khẳng định toàn bộ kết nối ổn định. Phép thử từ Vercel đã cung cấp lỗi xác thực chữ ký cụ thể hơn.

## Xử lý tiếp

1. Mở [R2 API Tokens của FPT - James](https://dash.cloudflare.com/63f67f18e38b4396d4a1b622bcc78990/r2/api-tokens).
2. Tạo token R2 mới với quyền **Object Read & Write**, giới hạn đúng hai bucket staging đã nêu.
3. Để phép thử không bị ràng buộc IP/thời gian ngoài ý muốn, kiểm tra mục IP filtering và thời hạn của token mới. Không sao chép IP hiện tại của máy vào điều kiện token dùng trên Vercel.
4. Lấy **Access Key ID và Secret Access Key từ cùng một lần tạo token**, thay cả hai giá trị trong `.local/deploy-cli/r2-credentials.env`, giữ quyền file 0600. Không dùng Account ID hay API token value làm S3 Secret Access Key; không gửi khóa qua chat.
5. Kiểm tra lại từ local và Vercel. Chỉ promote bản ứng dụng đầy đủ sau khi xác nhận đọc/ghi và luồng ảnh/export tương ứng.
6. Sau khi xác nhận cặp khóa mới hoạt động, xem xét thu hồi token cũ. Chưa tự thu hồi token cũ trong đợt chẩn đoán.

Sáu biến R2 đã được thêm vào target Production của Vercel để chạy phép thử có xác thực. Các deployment chẩn đoán dùng `--skip-domain`; không thay thế bản website đang phục vụ. Cặp khóa cũ đã bị thay thế. Cặp khóa mới đã được kiểm chứng; bản ứng dụng đầy đủ đã promote lên domain, health/admin/static đạt và các endpoint chưa xác thực bị chặn đúng. Các snapshot chẩn đoán đã được xóa.

Nguồn chính thức: [R2 credentials và permissions](https://developers.cloudflare.com/r2/api/tokens/), [R2 error codes](https://developers.cloudflare.com/r2/api/error-codes/), [boto3](https://developers.cloudflare.com/r2/examples/aws/boto3/).
